# 多窗口、覆盖层、屏幕共享与隐私权限

> 从原根 `AGENTS.md` §7、§8 迁出，并补充屏幕共享约束。

## 多窗口与 macOS 体验

- 定义主窗口、文档窗口、预览、编辑器、设置及覆盖层的身份、状态归属和恢复规则。同一文档的跨窗口编辑必须同步。
- 关闭窗口、关闭文档及退出应用分别处理。退出时协调未完成写入和后台任务，保存失败时不表现为安全退出。
- 正常退出按依赖顺序完成提交并释放资源；等待有界，超时提供明确选择。正常退出流程不作为强制退出时的可靠性保障。
- 遵循 macOS 菜单、快捷键、右键菜单、文件对话框、拖拽、撤销重做和窗口行为。处理焦点、中文输入法（组字期间不触发快捷键与提交）、全屏及 Spaces。
- 尊重系统主题、对比度、字体与缩放设置，兼容 Retina 和不同显示器比例。可交互控件有辅助功能名称、正确角色和键盘入口。

## 覆盖层

- 采用 `NSPanel`（`NonactivatingPanel` + `FullScreenAuxiliary`）及"底层原应用 → 中间可调蒙版 → 顶层浮动素材与笔迹"三层结构；明确绘制与鼠标穿透（`ignoresMouseEvents`）状态，提供快捷键和可发现的退出入口。验证多显示器、负坐标、缩放及全屏 / Spaces 切换。
- 当前 Tauri 原型创建的是 `NSWindow` 子类，只有传入真正的 `NSPanel` 时才设置 `NonactivatingPanel`。普通窗口不能靠增加该样式变成面板，也不得改写 Tauri 所有窗口的运行时类；当前原型尚未实现完整的非激活面板语义，不能据启动无警告声称已通过焦点验收。
- 区分画布、窗口、屏幕及设备像素坐标，通过明确的转换处理输入和渲染。覆盖层绘制不依赖屏幕采集授权；圈选取材时通过 `ScreenCaptureKit` 排除自身窗口截取底层画面。

## 屏幕共享（核心场景）

- **观众可见**：笔迹、激光笔、蒙版、浮动素材所在窗口必须能被会议软件采集（`NSWindow.sharingType` 保持默认可读）。
- **观众不可见（目标）**：浮动工具栏、模式提示、设置面板优先放在独立窗口并设为 `sharingType = .none`，让观众只看到内容。该行为在不同 macOS 版本与会议软件（腾讯会议、飞书、Zoom、Teams、Meet in Chrome）中表现不一致，**必须逐一实测并记录矩阵**；不可用时退化为"工具栏极简、可一键隐藏"。
- **共享模式差异**：会议软件"共享整个屏幕"时覆盖层可见；"只共享某个窗口"时覆盖层**不会**被采集。此时引导用户共享 Coboard 画布窗口（窗口内书写即观众可见）。UI 需在首次使用时说明这两种方式。
- 呼出覆盖层不得抢走会议软件或底层应用的焦点；全局快捷键不与常见会议软件快捷键冲突。

## 隐私、权限与外部输入

- 本地内容默认留在本机。向联网服务发送内容前，用户明确处理范围、服务去向并授权；后台恢复或重试不扩大原有授权范围。
- 系统权限仅在相关能力需要时申请并说明用途；拒绝或撤销后相关功能降级，本地编辑和保存继续可用。
- 凭据使用 macOS Keychain 或等效安全存储，不写入仓库、配置或日志。
- 导入文档、识别结果和 AI 输出视为不可信数据：限制体积与复杂度，校验格式和引用。WebView / IPC 暴露最小能力并校验消息来源。
- AI 结果作为候选内容交由用户接纳，接纳后可撤销；自动布局等操作可预览、可取消，遵循版本检查和编辑命令规则。
