# 面向失败、文件格式与错误诊断

> 从原根 `AGENTS.md` §4、§5、§10 迁出。存储提交协议见 ADR-002。

## 面向失败与数据可靠性

- 在文件、网络、解析、平台桥接和任务执行边界显式处理错误。Rust 使用 `Result` 和明确的错误类型；用户输入、外部数据和环境错误路径不得用 `unwrap` / `expect`。
- 每个写操作明确提交点、失败后的状态、可重试条件与恢复方式。重试有次数上限和退避，只用于暂时失败；权限不足或磁盘已满应提示可执行的下一步。
- 恢复能力建立在已提交的持久化数据、日志校验和启动恢复流程上，不依赖退出回调。明确尚未持久化内容的丢失窗口。
- 文件更新使用安全替换策略（同目录临时文件 + 完整性校验 + 原子替换）。原子可见性和断电耐久性分别验证。
- 跨文件更新（文档元数据与资源）使用暂存、提交标记及可重放的恢复协议。
- 保存、恢复、迁移和任务重试具备幂等性。非幂等操作使用稳定任务标识去重。
- 保存状态区分待保存、保存中、已保存和保存失败。"已保存"对应明确的持久化完成条件；失败时保留未保存内容并提供重试、另存或导出入口。

| 失败场景 | 必须考虑的行为 |
| --- | --- |
| 文件被占用、锁冲突或被外部修改 | 检测冲突，保留当前编辑，提供重试或另存 |
| 磁盘空间不足、只读卷或存储设备断开 | 保留最近有效提交及未保存状态，停止无效重试，提示选择其他位置 |
| 权限不足或已授权目录失效 | 保留数据，按需重新选择文件或申请权限 |
| 写入中断、强制退出或断电 | 识别完整提交，校验并重放可恢复记录，处理残留暂存文件 |
| 配置损坏 | 隔离损坏文件，用安全默认值启动；不连带重置用户文档 |
| 文档损坏或资源缺失 | 提供可恢复内容或只读打开；保留原件 |
| 文件版本较新或迁移失败 | 阻止不安全写入，提供只读或不兼容提示；迁移前保留副本 |
| 断网、服务超时、模型不可用或任务被取消 | 暂停对应任务，保留本地编辑，展示真实状态并允许重试 |

## 文件格式、路径与资源生命周期

- 文档采用 `.coboard` 包：`manifest.json`（Schema 版本与元数据）、`document.db`（SQLite WAL：快照、增量日志、时间线、FTS5）和 `assets/`（BLAKE3 内容寻址资源池）。识别生成的文字块或公式块保留原始截图切片哈希与来源坐标。
- 文档格式、配置和恢复记录设置版本及校验规则，定义兼容范围与迁移入口。读取未知版本时不得在保存中静默丢弃无法理解的数据。
- 应用数据、配置、缓存、日志及临时文件使用 macOS 标准目录；用户文档尊重用户选择的位置。
- 使用 Rust `Path` / `PathBuf` 及平台文件 API 处理路径，禁止手工拼接分隔符。区分文件 URL、显示名称和实际路径，处理空格、中文、组合字符及大小写差异。
- 导入、导出及相对资源引用检查路径边界，防止目录穿越。按需处理外接卷、网络卷及文件被移动或删除的情况。
- 按沙盒与分发方案管理文件访问授权；需要时使用安全作用域书签，正确配对开始、结束访问及失效恢复。
- 明确导入资料是复制进文档还是外部引用，保证离线可用性与界面预期一致。
- 文件句柄、任务、监听器、计时器、音频会话及 GPU 资源有明确所有者和释放时机。缓存可重建且有容量上限。

## 统一错误处理与可诊断性

- 统一错误模型，保留错误原因、稳定错误码、操作上下文和可恢复性；应用层决定恢复策略，UI 转为用户提示。用户取消与预期中断单独处理。
- 错误提示说明发生了什么、哪些内容已保存或受影响，以及下一步可做什么；优先提供重试、另存、重新授权等具体操作。
- 结构化日志记录操作名、关联 ID、修订信息、结果、耗时及错误链；按边界记录，同一错误不逐层重复。正常路径具备启动、保存和恢复诊断事件。
- 日志不包含画布正文、音频、凭据或 AI 原始请求；使用脱敏标识。日志轮转并限制容量，诊断导出需用户知情。
- 日志写入失败不阻塞创作。为恢复、迁移和保存失败保留可定位的诊断信息。
