# 启动、书写性能与资源预算

> 从原根 `AGENTS.md` §6 迁出。目标数值见 PRD 与 ADR-001 §4，均需实测校准。

- 启动优先展示可交互的窗口和画布；识别模型、AI 客户端等按需加载。数据库打开和恢复不阻塞 UI，**恢复期间也允许落笔**，提交在会话就绪后排队写入。
- 输入与绘制路径避免磁盘 I/O、网络调用、IPC 往返和长时间锁持有。笔迹增量更新，采用可见区域裁剪、空间索引及渲染缓存。
- 指针采样使用 `getCoalescedEvents()`（可用时）保留高频采样点；实时笔迹单独一层绘制，已提交内容另一层缓存。
- 图片、PDF、音频及大文档按页、分块或流式处理；限制解码后的尺寸、并发及内存。大列表使用虚拟化。
- 缩略图、纹理、撤销历史、事件队列及后台任务设定容量与清理策略。隐藏或空闲时减少刷新与轮询（激光笔动画结束即停止 rAF）。
- 在固定机型、系统版本、构建模式及数据集下建立基线，再设定可验证的预算。性能结论必须说明测量条件。
- 持续关注冷 / 热启动、输入到显示延迟、帧耗时、保存延迟、峰值与空闲内存，以及 CPU / GPU 和能耗。改动关键路径时提供与基线的比较。

## 空间与日常构建

- 日常使用 `npm run build:app` 的原生架构 release `.app`，不运行 Vite / Cargo 开发会话。性能测量同样用 release；调试应用只用于开发。
- 当前完整 `.app` 的文件字节总和预算为 **30 MiB**（非压缩包、非 APFS 块占用），由 `script/check-app-size.mjs` 在标准构建入口中执行；超限构建不交付。新模型、语言包或运行时纳入此预算，确有需要再以 ADR 调整，不能静默放宽。
- 保持 `opt-level = 3`，以 thin LTO、单代码生成单元和剥离符号减少体积；不以牺牲书写、识别吞吐为目的使用 `opt-level = "z"`。这些配置的实际运行性能仍须按固定数据集实测。
- 开发 `target` 缓存与安装体积分别报告。开发/测试关闭调试符号和增量缓存；日常开发保留依赖缓存，空间紧张时退出应用和开发进程后用 `npm run clean:build` 清理 debug，保留 release。不可在每次启动时自动清空缓存。
- 构建盘最低剩余 1 GiB，全量编译建议预留至少 3 GiB；这些是最低门槛和建议，并非所有工具链、架构与依赖组合的空间保证。运行已构建的应用不要求预留编译空间。
- 当前测量和兼容性边界见 [ADR-007](../decisions/ADR-007-lean-local-builds.md)。
