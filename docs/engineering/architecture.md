# 分层架构、模块边界与状态并发

> 从原根 `AGENTS.md` §2、§3 迁出。具体库选型以 `docs/decisions/` 中的 ADR 为唯一来源，本文只定义职责与约束。

## 分层

代码分离以下职责，依赖方向由外向内，领域规则保持独立。

| 层 | 负责 | 约束 |
| --- | --- | --- |
| UI / 展示层 | 窗口、覆盖层三层展示（底层穿透 → 中间可调蒙版 → 顶层素材与笔迹）、画布、文本与公式块、菜单、输入适配；**书写热路径（采样、平滑、笔锋、实时渲染、命中测试）** | 将用户意图转为应用命令；不直接写文件、调用外部 AI 或实现领域规则 |
| 应用层 | 用例编排、文档会话、任务调度、事务边界、IPC 命令 | 调用领域能力；通过接口使用存储、系统和网络服务 |
| 领域层 | 画布对象与推导卡片、笔迹与几何规则、编辑命令、撤销重做及不变量 | 不依赖 UI 框架、窗口对象、文件系统、数据库、网络或 macOS API |
| 基础设施与平台适配层 | 文档包与日志持久化、资源池、PDF、本地识别、联网 AI 适配、macOS 原生桥接 | 实现应用边界所需的接口；不决定业务规则 |

- 应用层依赖领域层及其接口，基础设施实现接口；在 `apps/coboard-desktop` 启动装配处连接具体实现。
- 每个模块有明确入口、状态所有者、输入输出和失败语义。crate 拆分以隔离变化及可测试性为依据，**有实现才建 crate**。
- 原生桥接集中封装于 `coboard-macos`，明确线程、资源所有权和生命周期；FFI / `unsafe` 记录 `// SAFETY:` 前提。
- 跨模块通过类型明确的命令、查询或事件协作，不直接修改对方内部状态。

## 状态、命令与并发

- 应用级状态、文档状态、窗口状态及可重建缓存分别管理，明确所有权和更新规则。
- 每份打开的文档有唯一的逻辑状态源和受控写入入口；多个窗口共享文档会话，各自持有视口、焦点和选区等视图状态。持久化状态、未保存编辑、任务进度和缓存必须可区分。
- 文档修改通过编辑命令执行，集中校验不变量并定义撤销语义。一次连续笔迹或拖拽合并为一个撤销单元；预览和手势中间态不提交文档。
- 多对象操作整体成功或保持原状态。撤销、重做及 AI 生成内容的接纳同样走编辑命令入口。
- 前端对已发出、未确认的编辑做**乐观显示 + 串行提交队列**：界面不因保存而锁定；失败时保留队列内容并可重试同一请求。
- 崩溃恢复日志、撤销历史、讲解时间线分别定义用途、保留策略和清理条件；撤销栈裁剪不影响恢复所需数据，缓存清理不删除创作历史所需资源。
- 文档提交与保存有明确顺序，使用稳定对象 ID 和修订号。后台任务返回结果时检查目标版本，防止覆盖用户新编辑。
- 阻塞 I/O、解析、索引和模型推理离开 UI / 输入线程。CPU 密集工作使用受控工作线程。
- 后台任务具备生命周期、取消、超时及并发上限。队列有背压机制。
