# 手写转文字评测方案 v1

2026-11-09。目标是由项目维护者主动发现常用字词失败，避免让用户逐个试错。本轮交付可运行的离线评测与失败基线，没有宣称修复了识别引擎。

## 责任与结论

通用样本整理、公开真人数据的来源核验、回放、分析和回归由开发侧完成，**不要求用户逐字提供样本**。只有另行开展个人字迹适配时，才可能需要少量本人笔迹；这不作为通用验收的前提。截图可以登记问题，不能自动当作带确定标签的数字笔迹：截图不含原始采样、笔顺和抬笔边界，人工看图的猜测也不能当标准答案。

当前识别未达可用门槛。必须保留明确的候选确认和“保留笔迹”，不能因为少量案例识别正确而将结果作为可靠的自动转写。引擎、分段和词表的进一步修改必须对比这个基线；不再只验证新反馈的单个词。

## 固定覆盖范围

[机器可读清单](../../research/handwriting/common-targets.json) 在本轮推理前确定英文词和诊断目标；中文常用字补足为 100 字。是日常演示词汇清单，不声称来自严格频率排名。以下各组分别统计，重复目标（如 good 同时属于常用词与易混项）不跨组去重。

| 分组 | 目标数 | 示例与目的 |
| --- | ---: | --- |
| 数字、大写、小写 | 10 + 26 + 26 | 大小写区分，0/O/o、1/I/l 等混淆 |
| 常用英文词 | 60 | good、hello、world、today、save、test、goal、memory 等 |
| 数字串与符号 | 12 | 2026、12345、3.14、50%、09:30、1+2=3 |
| 常用汉字 | 100 | 的、一、是、人、中、文、我、们、你、好、数、学等 |
| 中文短语 | 21 | 我们、你好、今天、保存、屏幕、共享、测试、微笑等 |
| 中英混写 | 12 | 中 API 30、版本 v2、你好 hello、good 好等 |
| 易混词形 | 14 | good/goal/god/food/pool、rn/m、cl/d 等 |
| 非文字负例 | 8 | 线、箭头、圆、矩形、叉、波形、螺旋、涂画 |

## 三套数据严格分开

1. **开发回归**：已反馈的 hello、memory、goal、我们，以及之后能恢复原始 XY 且标签确定的失败。必须每次全量回放。这些案例已参与调参，不能作为泛化准确率。截图中的新问题单独登记；新中文截图经用户明确确认为“微笑”，此前助手误读的“数学”不作为标准答案。当前该截图没有对应原始 XY，保留为已确认失败证据，尚不冒充已完成轨迹回放。good 截图的文字推断也不作为真人标准答案。
2. **结构诊断**：使用公开 UJI 真人单字笔迹，以同一书写者、同次重复，统一高度、基线和字间距拼成常用词。检查单字分类、分段、候选排序、中英文竞争，以及逐笔追加与重试。它不是自然连笔，也不能替代真实英文词准确率。平移、缩放、采样加密等同源变体也只进入这一层，不能扩充独立样本分母。
3. **独立验收**：数字/字母可以使用公开真人孤立字符；单词、中文短语、混写必须使用自然书写的原始数字笔迹。目标每项至少 20 位独立书写者，开发/验收按书写者隔离；验收标签在推理后才用于评分。现有专有模型训练集未知，不能声称其训练集从未包含公开语料。

公开数据由开发侧获取和导入，保留来源、许可、版本、原始及转换文件 SHA-256、坐标方向、笔顺、书写者/采集分组。先确认可用范围再使用；不上传用户画布，不使用字体轮廓、AI 造字或单字拼接冒充多人自然字迹。如果数据获取受阻，报告具体来源与障碍，不能把“缺样本”转交用户。

当前独立验收只覆盖 UJI 的 62 类字母/数字。中文、自然词、连笔、混写与非文字负例尚缺独立自然笔迹；报告因此判未通过。这个状态不妨碍已经完成的分类和分段诊断，也不要求用户为评测补录全部目标。

## 两条回放路径

- **最终快照**：通过与桌面 IPC 相同的 `HandwritingRecognizer::recognize`，保留全量原始笔画；每个样本使用新会话，语言范围与桌面一致。它包含模型、空间分段、英文连笔分支、候选竞争，不只测单字分类器。目标标签不传入分类/解码函数。
- **逐笔追加**：固定前两位 UJI 书写者的第一遍常用词等诊断样本，加全部历史轨迹，每次抬笔追加一笔；检查整个响应的幂等重试与返回笔画 ID。每个请求保存中间候选及稳定前缀。推理错误照样记入样本分母；失败后停止该样本并继续其他样本。

后续增加多笔连写、迟到的 i 点/t 横、笔画替换/删除、乱序旧响应、候选确认后的转换/撤销，分别检查识别与文档行为。已有普通单元测试仍继续运行，不用模型评测替代编辑安全验证。

## 指标与暂定门槛

指标分别按数据角色、语言、目标词统计，不能把开发集、拼接集、重复回放混成一个“准确率”。主要指标严格区分大小写和空格；不擅自将 O 改成 0、去空格或替用户纠错。

- 首选整串命中率 Top-1、前五候选整串命中率 Top-5；候选中存在答案不等于首选正确。
- CER：编辑距离总和 / 正确文本字符总数，包含错字、漏字、多字；可能超过 100%。推理失败按空输出计，不能删除。负例另记误提供文本候选率。
- 中文挤占英文的首选数量、逐词失败清单、推理错误；保留所有失败，不只列典型成功。
- 稳定前缀错误次数、返回笔画身份不一致、幂等重试不一致。稳定前缀是正确性诊断，不能把它当已确认文字。
- 原生每请求计算 p50/p95/max 与模型准备时间分开；最后一次追加的时间不代表整个词处理时间。原始记录另保留每个请求与累计处理时间。
- 抬笔 → 前端排队 → IPC → 候选实际绘制需独立测量；原生函数时间不叫端到端延迟。

暂定验收要求：每目标至少 20 位独立自然书写者；单语分组 Top-1 ≥95%、Top-5 ≥99%，混写 ≥90%/98%；原生计算 p95 ≤200ms；窗口端到端 p95 ≤300ms（需另行真实测量）；负例误提供候选 ≤1%；推理错误和笔画身份/重试错误为 0。门槛是产品目标，不是已经观察到的能力。评分器单独计算离线门槛，完整交付仍需 UI 验收；它不会仅凭离线结果返回已验收。

任何引擎修改都先全量回放、按样本比较新增失败；不接受以中文下降交换英文提高而只汇报总分。若对某独立集调参，该集转为开发集，另留书写者隔离的验收集。失败原因分为采样/预处理、单字模型、切分、语言竞争、会话、文档/UI，再决定修哪一层。

## 一条命令复现

无需新增依赖，全程本地 CPU。使用已有 UJI 转换文件，哈希必须与 [来源清单](../../research/handwriting/human-uji-manifest.json) 一致；原始 ZIP 的获取与转换见 [UJI 说明](../../research/handwriting/human-evaluation.md)。模型沿用本机研究资产，其分发许可问题不因本次评测改变。

```sh
python3 research/handwriting/run-common-eval.py \
  /private/tmp/coboard-human-ink/uji-test.json /tmp/coboard-eval-new
```

新建输出目录，保存输入、逐请求输出、汇总、环境、模型/词表/源码哈希。退出码 0 表示完整验收通过，1 表示未达门槛，2 表示运行/数据/报告完整性异常。当前预期为 1，不能改成绿色测试冒充通过。可以附加书写者数进行冒烟，但不能将小样本冒烟当完整验收。

```sh
python3 research/handwriting/test-common-eval.py
cargo test --offline --locked -p coboard-vision-ml
cargo fmt --all -- --check
cargo clippy --offline --locked -p coboard-vision-ml --all-targets -- -D warnings
```

评分器对缺失样本、重复终态、未知 ID、缺漏/重复/乱序抬笔结果直接报错，避免中断的运行看起来准确率很高。错误和空候选始终留在分母。测试覆盖这些评分完整性要求。

首轮实际结果与限制见 [评测基线](../../research/handwriting/common-eval-baseline.md)。
