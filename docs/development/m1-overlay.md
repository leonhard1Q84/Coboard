# M1：屏幕覆盖层原型

日期：2026-11-08。当前为可运行原型，不代表屏幕共享兼容性已完成验收。操作见 [屏幕讲解指南](overlay-guide.md)，手写直出见 [引擎调研](handwriting-engine-research.md)。

手写状态更正：本文 PaddleOCR 构建、启动和合成样例记录属于历史验证；用户已否决其直接书写体验。用户要求免费本地替代；候选验证结果见引擎调研，新引擎尚未接入。见 [ADR-005](../decisions/ADR-005-incremental-digital-ink.md)。

## 当前实现

- `overlay` 承载笔迹与 alpha 压暗背景，`overlay-toolbar` 独立承载控件与模式提示。全局 `⌥Space` 呼出／收起、`⌥P` 切换穿透。
- `Canvas` / `Toolbar` 在画布与覆盖层复用：5 种笔刷（圆珠笔、铅笔、钢笔、记号笔、荧光笔）、临时激光、整笔擦除、单选移动、删除、文字与公式源码、规范图形。
- 直线、箭头、矩形、椭圆可拖出。直线、矩形、椭圆支持用户开启后停笔 600ms 规整，以及对选中笔迹规整；该能力是简单几何拟合。
- 屏幕标注的撤销重做、擦除与清屏使用相同编辑路径；清屏可撤销。标注只在进程内保留，收起不删除，退出丢失。
- 工具栏按内容高度自适应，帮助、笔刷与背景菜单不再溢出固定 52px 窗口；可收起绘图行，保留模式切换与退出入口。
- AppKit 窗口操作统一调度到主线程。原生失败不再在 UI 中假装已经切换，显示错误反馈。
- 默认只压暗 25%，去色与模糊未验证，界面不提供对应滑块。透明 WebView 的 CSS 滤镜不能作为过滤其他原生窗口的证据。

## 原生边界与未验收项

- 当前用 Tauri 的 WebviewWindow / NSWindow 配置 `NonactivatingPanel` 样式；并未替换底层对象为自定义 NSPanel 子类。全屏、Spaces、不抢焦点与文本编辑的平衡需进一步实测。
- 绘图窗设可共享，工具栏设 `sharingType = none`。这是隐藏控件的尝试，不能推出腾讯会议、飞书、Zoom、Teams、Chrome Meet 都会排除它；完整会议软件 × macOS × 整屏／窗口共享矩阵未验收。
- 呼出定位到主画布所在显示器，一次一个显示器；跨显示器绘制、不同缩放比例与热插拔仍需实测。
- 手写文字已接入 PaddleOCR.js 本机 Worker / WASM 原型，W 启用，停顿 1.2 秒后转换，可撤销恢复整组笔迹；未认清保留原笔迹。真实用户字迹与输入速度未完成验收。屏幕截图、截图 OCR、识别原图、素材编排、带入画布与屏幕标注持久化均未完成。

## 手写引擎集成验证

- 隔离 WKWebView 加载生产构建 Worker，使用自定义应用协议、本地模型与 WASM、1 线程、无网络；三组手工构造的矢量笔迹（不是用户样本）分别输出 `HI`、`中文`、`中API30`。第三组期望 `中 API 30`，空格丢失，单独记录未达标。
- 修复 SDK 在 Worker 内默认 ImageData 路径依赖 `document` 的问题，改用 SDK 支持的 OpenCV Mat 入口并显式释放 Mat。
- 固定 2× 放大会让本次中文样例检测漏字；按较高笔画高度归一化后恢复。检测框未覆盖任一笔迹时保留整组墨迹，避免部分转换丢字。
- 本次 Apple M4、arm64、macOS 15.6.1、WKWebView、WASM 单线程三次推理分别约 86 / 54 / 58ms，不含 1.2 秒停顿和冷启动；仅为本机单次合成样例诊断，不是 p50/p95、真实手写准确率或桌面交互性能结论。
- 独立 Coboard Ink Preview 应用构建启动成功（debug 84.42 MiB）；未对最新全部绘图／文字／穿透交互进行 GUI 验收。未重启已有 Coboard 及用户已使用的上一版预览应用。
