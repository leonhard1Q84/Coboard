# 手写候选的本地计时

纯推理耗时不能替代抬笔到候选出现的延迟。前端现在从真实 `pointerup` 的事件时间戳开始，将该时间随最新待处理快照保留，覆盖一个在途请求导致的等待。相同笔迹的文档重绘不重新起计时；移动、删除等没有抬笔来源的更新不混入统计；过期返回不计。

在实际 WKWebView 的开发者控制台显式执行：

```js
window.coboardHandwritingMetrics.start();
// 在前台窗口正常书写，等待候选显示；然后导出纯耗时。
JSON.stringify(window.coboardHandwritingMetrics.snapshot());
window.coboardHandwritingMetrics.stop();
```

默认关闭。只在当前窗口内存保留最近 256 个样本，不保存笔迹、识别文字、会话或笔画 ID，不写磁盘，不输出日志，不上传。`start()` 清空上一轮；`stop()` 使未完成记录失效。

每个样本包含：

| 字段 | 边界 |
| --- | --- |
| `queue_ms` | 抬笔事件到客户端提交 transport，包含前端等待 |
| `roundtrip_ms` | transport 提交到对应 Channel 结果回调，包含桥接、原生排队、可能的模型加载与推理 |
| `compute_ms` | 后端解码器报告值，沿用原范围，不含模型加载与 IPC |
| `pen_up_to_presentation_opportunity_ms` | 抬笔到候选 React DOM 提交后的第二次 rAF，覆盖一次浏览器绘制机会 |

第二次 rAF 是可复现的浏览器调度边界，不能证明显示器实际发光时间。记录期间隐藏过窗口的样本、未显示候选的覆盖层、候选被更新或取消而来不及呈现的样本均不计。它只测候选反馈，不能代替稳定文字排版延迟；当前仍需用户选择候选转换。

测试验证了排队合并使用最后一次抬笔时间，以及取消、后台切换和无抬笔更新的排除。尚未收集新版实际窗口的 p50/p95；完成真实窗口采集前不宣称达到 ADR-005 的 200ms 候选目标。每次测量需另记机型、系统、构建模式、输入设备、样本及首次启用/热态分组，不能把第一次模型准备混入热态后隐去。
