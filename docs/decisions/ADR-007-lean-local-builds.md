# ADR-007：日常使用精简 release 应用，分开管理构建缓存

- 状态：已采纳
- 日期：2026-11-10

## 问题与范围

小磁盘机器曾因仅剩 0.40 GiB 而停止构建。此前本地运行脚本始终打包 debug；开发目录混有依赖、测试产物和四份旧调试 `.app`，并不能代表用户安装应用的大小。产品侧已明确手写按当前可用范围收敛，重心回到屏幕共享讲解的常见任务、性能和空间占用。

## 决策

- 根目录 `npm run build:app` 构建当前机器架构的 release `.app`，校验签名、检查体积并输出路径，不重启会话；`script/build_and_run.sh` 默认构建运行 release，`--debug` 保留调试入口。暂不生成双架构 universal 包或额外安装器。
- release 使用 `opt-level = 3`、thin LTO、一个代码生成单元、无调试信息并剥离符号。保留 panic unwind；不为减少体积改成 abort 或改动存储恢复行为。首次优化编译的成本高于增量开发，之后日常使用直接打开 `.app`。
- 标准构建入口检查完整原生架构 `.app` 的逻辑文件字节总和不超过 30 MiB，包括可执行文件、资源和签名；超限返回失败。预算变化必须有新的测量与决策依据。该预算不涵盖开发缓存和用户创作内容。
- `npm run clean:build` 仅经 Cargo 清理 dev/debug 产物，包括旧 debug 应用、测试与依赖缓存；保留 release 与本地文档。先检查 Coboard、Tauri、Cargo 进程；检查失败或发现运行中的任务时拒绝执行。不在启动时自动清理，也不停止用户会话。清理会让下一次开发重新编译。
- 不引入新依赖，不捆绑额外手写模型。现有 Loro 参与格式 v1 的日志、快照与校验，本轮保留其兼容性；本地资源网关的替代仍沿 ADR-003 单独推进，避免把存储/平台迁移混进构建调整。

## 体积基线

条件：Apple M4 / MacBook Air Mac16,12，16 GiB，macOS 15.6.1，arm64；Rust/Cargo 1.98.0，Node.js 25.6.1；锁文件依赖；2026-11-10 本地测量。目录体积按递归 `lstat.size` 求和，缓存按 `du -sh` 观察，两种口径分别列出。

| 产物 | 文件字节总和 | MiB |
| --- | ---: | ---: |
| 调整前留存的 `target/debug/bundle/macos/Coboard.app` | 61,086,904 | 58.26 |
| 当前 `npm run build:app` 的 release `.app` | 15,661,672 | 14.94 |

相较留存 debug 包减少约 **74.4%**。旧包并非当前源码的受控对照构建，因此该数字是实际日常产物的比较，不能全归因于某一编译选项。前端本轮未变更，仍完整携带公式字体与渲染器。

现有实验手写模型仍从本机外部目录按需读取，未包含在上述 `.app` 字节数中：分类数据 3,950,080 bytes，语言数据 2,033,252 bytes，共 **5.71 MiB**。应用加这两份资源合计约 **20.64 MiB**，不含用户文档。其他机器仍须按 [增量手写实验](../development/incremental-handwriting-prototype.md) 配置已有模型，缺模型时保留墨迹；本轮没有改变这项现有限制。

检查时原有 `target` 约 2.7 GB，其中 debug 约 2.6 GB，四份旧 debug 应用共约 235 MB。新增 release 编译后 release 缓存约 1.3 GB；安装应用仍仅 14.94 MiB，不能将编译缓存当成安装体积。现有 debug 会话运行中，因此没有清理其缓存或重启它。

## 验证与限制

- `npm run build:app` 完成 release 编译、打包、完整 ad hoc 签名校验和 30 MiB 体积检查。
- `node --test script/build-tools.test.mjs` 验证缺可执行文件/超限资源会失败，以及运行中应用、构建、进程检查失败会阻止清理；清理测试用假 Cargo 验证仅传入 dev profile，不删除真实缓存。
- 前端构建与测试、Rust 测试、fmt 和 clippy 另行运行并在交付中报告结果。
- 本轮未测量 release 的冷启动、书写延迟、CPU 或内存，不能以包体积减小推断这些指标改善；未关闭当前用户会话执行 GUI 恢复验收。现有真人笔迹评估的限制继续有效，范围收敛不等于识别准确率已经达到 90%。
- 本地 ad hoc 签名依然不代替 Developer ID 与公证；移交用户前继续遵循 ADR-006 的完整签名检查。
