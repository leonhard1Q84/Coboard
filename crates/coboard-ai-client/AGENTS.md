# coboard-ai-client 规范

> 从原根 `AGENTS.md` §9 迁出。本 crate 目前为空壳；有实际实现前不扩展。

- 联网能力（AI 理解、语音转写、文档生成等）通过统一的服务客户端抽象访问；领域层和应用层依赖接口，不直接耦合特定服务商的 SDK、HTTP 端点或请求格式。服务商切换或新增不应修改调用侧逻辑。
- 请求构造与响应解析集中在客户端适配器中。请求体的序列化格式、认证头注入、重试与退避策略由适配器统一处理；应用层只关心"发送什么内容、期望什么结果、如何处理失败"。
- AI 请求发送前必须确定内容边界和大小预算。画布快照、图片、音频等多模态输入需压缩或裁剪到合理范围；不得将整份文档无限制地序列化为请求体。内容预算应作为可配置参数，并在超出时向用户说明裁剪范围。
- 模型选择、提示模板和输出格式约定作为配置管理，不硬编码在业务逻辑中。提示模板随代码版本管理；模型标识和 API 版本变更应能在不重新编译的情况下调整。
- 流式响应须支持增量消费和中途取消。部分到达的内容不提交到文档状态，仅在用户确认接纳或流完成后才进入编辑命令流程。流中断后清理已分配的临时资源，不留悬挂状态。
- 超时分层：连接超时 < 单次请求超时 < 任务级超时。超时值可配置；流式长连接使用心跳或进度检测区分"正常等待"与"连接丢失"。
- 幂等请求（理解、识别）结果可缓存，缓存标记模型版本和输入哈希，变化后失效。非幂等操作（如消耗配额的生成请求）不自动重发。
- 凭据生命周期明确：获取、刷新、失效和吊销。Token 过期自动刷新，刷新失败后暂停依赖该凭据的任务并提示重新授权，不静默丢弃请求。多服务商凭据隔离存储。
- 错误分类：429 退避重试；401/403 刷新凭据或重新授权；5xx 有上限地重试；4xx 业务错误直接反馈用户，不重试。
- 诊断日志记录请求 ID、目标服务、耗时、状态码和错误类型，不记录请求正文、响应正文、API 密钥或用户内容。
- 适配系统代理、PAC、环境变量；TLS 校验失败给出可操作提示，不通过禁用证书校验绕过。区分暂时性与持久性的 DNS / 连接失败，避免对无法连接的服务持续重试。
